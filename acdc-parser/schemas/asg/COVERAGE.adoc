= ASG coverage and boundaries

acdc has two checked ASG output contracts. `Profile::Upstream` uses the unchanged
pinned draft schema. `Profile::Acdc` uses `urn:acdc:asg:1`, a separate, closed
extension. Parser `CompatibilityMode` selects language behavior independently.
Neither profile reparses content, runs a converter or repairs the document.

Native JSON remains a separate representation. In particular, retained positional
slots and resolved semantic state can be absent from native JSON. The exporter
reads semantic owners directly. A native JSON value failing ASG validation does
not establish that its parser result is wrong.

== Graph checks

Document attributes and scalar metadata cannot impersonate nodes by using names
such as `name`, `type`, `id` or `number`. Identity discovery visits semantic owners;
retained catalog labels do not register another copy of an inline identity.
Duplicate real IDs and stale reference registrations still fail.

Every exported positive footnote number must link to a canonical definition with
the same optional ID. This includes independent reference labels and captured
index labels. The canonical root definition owns the body. A historical body
copy in a captured label does not replace it or become a second definition.
Native authoritative occurrences still receive their existing body/cycle checks.
A zero-number unresolved reference stays unresolved; a zero-number definition
fails. Standalone inline export requires document context for any footnote,
including one retained only in a catalog label.

== Explicit limits

Neither contract claims every native state is exportable. Bibliography anchors,
nondefault section category/numbering, nondefault xref style/caption/signifiers,
protected document values with insertion behavior, ambiguous scalar state and
unresolved substitution instructions retain typed errors. Invalid locations,
unsupported block/cell forms, stale catalogs and contradictory prepared graph
state also fail. Errors identify the unsupported owner or property with a JSON
Pointer; export never emits a partial graph or drops a semantic field to pass.

Absent content remains absent. Present empty content stays `[]`. Export does not
invent source ranges, image fallback text, menu separators, mathematical syntax,
callout destination links or asset resolution. Keep the named profile when its
richer meaning cannot fit an upstream contract.

== Validation scope

The fixture audit checks source/expectation pairing, every native JSON value,
model/property inventory and source locations. Its schema success counts describe
native-format overlap with the pin. They are not checked-export success counts.
The ASG tests separately validate strict and named exports, semantic invariants,
negative cases and nested combinations in both compatibility modes.

The official TCK checkout at `cdfada9c2768b164eadf4bc12e9f9c68e6caf68a`
contains 13 cases. The checked strict adapter passes 11 and fails two:

* Listing `multiple-lines`: the native listing retains unnumbered caption state.
  The pin has no field for it, so strict export rejects
  `/blocks/0/metadata/caption`. The named profile preserves that state.
* Section `title-body`: the real generated `_section_title` ID is exported, while
  the TCK expectation omits it. The pinned schema permits the ID. Removing it only
  for the comparison would hide actual target identity.

These remain failures. A larger passing fixture suite does not replace them or
prove full language conformance. Upstream caption semantics and generated-ID
canonicalization need explicit agreement; the exporter does not change meaning
to match an expected object. No TCK expectations or pinned schema bytes change.

== Versioning and upstream discussion

Keep the pinned upstream revision and named profile distinct. A future accepted
upstream representation needs its own reviewed projection and tests; consumers
must not infer a schema revision from an unchanged draft identifier.
The link:proposals/README.adoc[proposal material] separates possible core content
additions from unresolved caption state and later extension families. It has not
been submitted upstream. Upstream acceptance is not a requirement for using the
explicit local profile.
