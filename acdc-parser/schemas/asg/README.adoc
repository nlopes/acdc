= Pinned ASG schema and model inventory

`schema.json` is an unchanged copy of the AsciiDoc ASG draft at
https://gitlab.eclipse.org/eclipse/asciidoc-lang/asciidoc-lang/-/blob/68ed0b22e8d9b919897542d8ae14f03e7dbdd2e4/asg/schema.json[revision 68ed0b22e8d9b919897542d8ae14f03e7dbdd2e4].
Its identifier is `https://schemas.asciidoc.org/asg/1-0-0/draft-01`.
Its SHA-256 is `61fc73c612d7fe79e795dc0db2fd8bf8393d146dfcc8815fa7feca864f769675`;
its upstream Git blob is `71f41d7b02675c14c9b298b53e85f737a26bf19c`.
The identifier alone does not pin its contents.
The accompanying `LICENSE-EPL-2.0` and `NOTICE.adoc` come from the same revision.
The Rust audit code uses the crate's normal license.

== Run the audit

From the workspace root:

[source,console]
----
cargo run -p acdc-parser --example asg_schema_audit --all-features --locked --offline
----

The command writes a JSON report to stdout and never rewrites fixtures.
It checks the schema pin, validator controls, fixture pairing, every native
JSON expectation, and locations throughout the tree, including unsupported
nodes. Parser diagnostics are separate expectations and are not treated as ASTs.
Supporting files under `includes/` are excluded from fixture discovery.
Every outcome or diagnostic expectation needs an owning `.adoc` source.
There are no orphan exceptions; the former empty `document_title.json` was removed.

A native audit exits successfully when it completes, even when native values
do not fit the ASG schema. Read `counts`, each file's `schema_errors`, and
`location_findings`. These are native-format observations, not successful ASG
exports or AsciiDoc conformance results. File names are relative to the fixture
root. An unreadable file or invalid fixture layout fails the command.
Use `--fixtures DIR` to audit a different fixture directory.

To validate supplied ASG JSON, add `--validate FILE...` after `--`.
This mode exits unsuccessfully if any supplied file is invalid JSON or fails
schema validation. Errors include both instance and schema JSON Pointer paths.
Validation does not fetch a moving schema or enable HTTP reference retrieval.
The validator reads the exact vendored bytes. The schema's `defaults` annotations
do not insert values or change the input.

The controls include a formatted title, a structurally invalid title, an unknown
property, and a schema-valid title with deliberately wrong text. The last case
shows why schema validation cannot prove that an exporter preserved meaning.

== Read the inventory

`support-inventory.json` lists every top-level backing-model struct, enum
variant and payload, and alias. This includes nonserialized semantic properties
and separately classified parser/source helpers. A test compares its declaration
and field coverage with the current Rust sources. The inventory is an internal
mapping record, not a promise about public AST storage or a checked export API.
Shared policies are defined once; each property names its policy and any upstream
schema location. Each declaration also names a strict-export group with its current
handling and executable evidence. Tests reject missing groups and stale evidence.
Extension records also check their owner/property names, schema pointers and test
references against the current files.

[cols="1,3",options="header"]
|===
|Classification |Meaning
|`mapping-candidate` |The schema has a possible representation. The owner and every nested semantic value still need a tested, lossless mapping.
|`context-dependent` |Representation depends on the owner, form, presence, or effective controls. Preserve the meaning or reject it.
|`reject` |No lossless upstream representation is established. This applies at any nesting depth.
|`source-only` |Source spelling or temporary parser state can be omitted after its meaning and permitted provenance are preserved.
|`derived-check` |A catalog can be omitted only when supported exported owners retain everything needed to reconstruct it. Otherwise reject it.
|===

A compatible child or metadata field does not make an unsupported owner
representable. Block titles and reference text have inline-array fields in the
schema. Formatted attribution, citation, caption, alternative text, and tooltips
must not be flattened into metadata strings just to pass validation.
Inline images, icons, UI macros, footnotes, index terms, tables, several span
variants, inline identity/controls, and ordered body assignments need explicit
support or rejection. Delimited admonitions have a schema form; paragraph
admonitions must not acquire an invented delimiter.

Block positional slots must come from the authoritative owner, including gaps
and empty values. Native JSON can omit those slots and other semantic state;
serializing native JSON and rewriting it is not a complete export strategy.
Export must not expand attributes, parse strings again, register macros, or run
a converter. Missing and empty values remain distinct where they carry meaning.

The location audit checks every serialized location and reports nodes without
one. An unavailable optional location can be omitted by an exporter; a required
unknown location must fail export. Never invent line zero or replace it with
one. Line/column validation does not prove original byte-offset correctness,
include-chain fidelity, or correct source attachment.

Changes to this schema pin require a reviewed mapping and new validator controls.
Keep extension schemas separately named and versioned; do not edit the upstream
schema to make native JSON pass.

== Checked upstream export

Enable the `asg` Cargo feature and call `asg::document(parsed.document())` or
`asg::inlines(parsed.content())`. Export reads the AST directly, then validates
against this pin. It returns a complete JSON value or a typed error with a
JSON Pointer path. Unsupported-value and invalid-location errors identify the
nearest semantic owner and retain its coordinates when known. An unknown inner
location stays unknown; an outer document range is not substituted for it.
Schema loading and invalid projected output have separate error variants.
It never expands attributes, parses strings again, registers
macros, or invokes a converter. Native JSON and parsing behavior stay unchanged.

The initial subset includes document attributes, headers/authors, paragraphs,
ordinary unnumbered sections, plain text, raw text without remaining
operations, raw text with exactly one escaping stage, resolved typographic
symbols, strong/emphasis/code/mark spans without inline IDs or roles, and supported
links and cross-references. Ordered, unordered, callout and description lists retain
their item structure.
Supported delimited, leaf and macro blocks retain their actual forms and bodies.
Titles and reference labels retain their inline structure and empty presence.
Document presence is an empty string, explicit unsets are null, and integers
retain their attribute-reference spelling. Protected document values are rejected
when their insertion behavior cannot fit a scalar string.

Block metadata retains string attributes, true presence, styles, ordered roles
and options, and retained positional slots. A gap omits its `$N` key; a retained
explicit empty value emits an empty string. Positional values remain available
after callers edit named attributes. Conflicting `$N` names, unset or ambiguous
scalar values, multiple IDs, bibliography meaning, and independent reference
labels are rejected. A primary block ID and its selected reftext are promoted
to the block. Source coordinates of the ID token have no upstream field.

Unsupported values include uncovered block forms, other inline macros, missing span
variants, inline identities/controls, subtitles/header metadata, ordered body
assignments, captions, attribution/citation, unresolved substitution instructions, and
nondefault section category/numbering. Verbatim leaves require a supported literal, listing or verse body; they cannot
be flattened into ordinary paragraph text.
A section without a title is rejected, while a present empty title stays an
empty array.

Character references retain their named identity or canonical decimal numeric
value. The parser identifies them during replacements, according to the selected
compatibility mode and substitution order. Literal ampersands and escaped
references stay text. Export never infers reference meaning from a string.
Invalid XML numeric values fail export; unknown names retain their identity.
Protected literal text and raw output remain distinct supported forms.

Ordinary line and delimited source comments and parser/edit history can be omitted.
A title or semantic metadata on a delimited comment is rejected, rather than omitted. Derived
reference and TOC entries can be omitted only when their titles, labels, category,
and numbering agree with supported exported owners. Extra or stale catalog
meaning is rejected; exporting does not repair catalogs. Byte offsets and ID-token
coordinates have no upstream fields. Completely unknown optional locations are
omitted; partially known or invalid coordinates fail. Export success does not
promise source reconstruction or complete AsciiDoc conformance.

== Strict-export coverage

These groups describe the current checked subset. Helper and payload types inherit
their owning construct's decision; membership does not promise independent export.
The property inventory remains authoritative for each declaration.

[cols="2,1,5",options="header"]
|===
|Group |Declarations |Current handling
|`core` |7 |Documents, headers/authors, paragraphs and ordinary sections; recurse into all owned content.
|`literal-content` |13 |Resolved text/references and four span forms; reject unsupported controls and verbatim context.
|`block-metadata` |7 |Preserve supported scalar values, identity and slots; reject unsupported presence or independent meaning.
|`document-values` |7 |Preserve resolved assignments; reject protected insertion behavior.
|`catalogs` |3 |Omit reconstructible entries; reject extra or stale meaning.
|`locations` |4 |Preserve known endpoints/include chains; omit unknown optional locations; reject invalid ones.
|`dispatch` |4 |Exhaustive owner decisions; a rejected owner rejects its entire subtree.
|`source-state` |8 |Omit comments and resolved routing/history; retain effective values and IDs.
|`pending-content` |3 |Reject unresolved content.
|`substitutions` |7 |Preserve resolved settings through text/raw nodes; reject unknown instructions and pending raw operations.
|`decorations` |12 |Accept default section policy; reject numbering, category, captions and attribution/citation.
|`body-assignments` |2 |Reject ordered assignments and retained events.
|`inline-controls` |4 |Reject identities/roles on supported spans and populated controls on unsupported macros.
|`references` |11 |Preserve link/xref targets and effective labels; reject unsupported controls and ambiguous target classification.
|`lists` |11 |Preserve list families, markers, terms, principal and nested content; reject checklists and unrecoverable item state.
|`blocks` |9 |Preserve supported forms, bodies and media targets; reject missing provenance or unsupported content properties.
|`unsupported-owners` |37 |Reject the entire block, inline, macro or payload without inventing a form.
|===

The evidence covers positive mappings, rejected owners/properties and permitted
omissions. Adding a model declaration or field requires an inventory decision;
adding a mapping also requires semantic assertions beyond schema validity.

== acdc extension profile

`asg::document_with_profile(document, asg::Profile::Acdc)` selects
`acdc-v1.json`, identified by `urn:acdc:asg:1`. Each extended document includes
that identifier in its required `profile` field. This is an acdc format, not
upstream ASG conformance. `asg::document` and `Profile::Upstream` keep the strict
upstream contract. Parser compatibility mode and output profile are independent.

The schema is a separately named derivative of the pinned schema, under the
same EPL-2.0 license and notices. Its closed definitions are changed directly;
adding an `allOf` sibling would not extend a closed upstream object. Tests compare
the complete derived schema with the pin and allow only the documented additions.
Both validators use local schema bytes and do not fetch references.

Titles and reference text keep the upstream inline-array representation.
Attribution and citation use `attribution` and `citetitle` inline arrays on their
owning block. An absent field stays absent; a present empty field becomes `[]`.
Literal values stay text nodes, and parsed formatting keeps its nodes. Export does
not expand attributes, parse strings, or duplicate raw metadata strings.

A block's resolved `caption` has one of three closed forms:

* `{"kind":"unnumbered"}` retains caption-capable state without a prefix.
* `{"kind":"custom","prefix":[...]}` retains an explicit prefix as inline content.
  A literal programmatic prefix becomes text without an invented source location.
* `{"kind":"numbered","counter":"example","label":"Example","number":1}`
  retains the counter, literal label and assigned ordinal. The other counters are
  `figure`, `listing` and `table`. An unassigned ordinal omits `number`; it is not zero.

This supports captioned listings and examples, including their retained titles
and reconstructible reference catalogs. A stale catalog still fails export.
Cross-reference controls, unsupported inline nodes, header metadata and other
uncovered semantics retain their explicit errors.
Nested content is checked under the same schema; unknown fields are invalid.
`support-inventory.json` records these additions separately from strict support.

== Images in the acdc profile

An inline image has `name: "image"`, `type: "inline"` and its complete `target`.
Optional `alt` and `tooltip` fields are inline arrays, including `[]` for explicit
empty values. Omitting `alt` retains the filename fallback policy; export does not
invent fallback content. A block image has macro form and an optional `alt` array.
Its block title and resolved caption remain separate; it has no inline tooltip.
The schema permits block `alt` only on image macros, not audio, video or TOC nodes.

Inline image IDs are promoted to `id`. Scalar controls, such as dimensions and
links, stay in `metadata.attributes`; roles and options retain their order.
Values stay strings, including numeric spelling, and true presence becomes an
empty string. Unset or ambiguous scalar state fails explicitly. Macro/node and
content locations are retained; ID-token coordinates follow the documented
source-only omission policy. No HTML tags or output escaping are introduced.

Images compose through supported spans, link labels, document/block titles,
reference text, captions, attribution and citation content. Every recursive call
uses the selected profile. Unsupported nested nodes and unknown or malformed
image fields fail; an extension does not enable arbitrary macros.
`asg::inlines_with_profile(content, Profile::Acdc)` applies the same checks to a
standalone array. Strict document and inline export keep their upstream errors.

== References

Links, URL macros, mail links and autolinks export as `ref` with variant `link`.
Explicit labels keep their inline tree. Automatic link labels become their effective
text, including URI scheme hiding, without changing the destination. Generated
label text has no invented source location. Bracketed email autolinks keep their
angle brackets as text outside the reference.

Mail query values are percent-encoded in the destination; body line endings become
CRLF. Existing unrelated query headers retain their spelling. Positional subject
or body values replace only the corresponding query headers, including explicit
empty values. The visible fallback label still uses the original destination.

Cross-references export as variant `xref`. An empty `inlines` array retains automatic
label selection; the exported target owns its title and reftext. Export does not
copy a computed label into the reference or resolve it again. Nondefault styles,
caption labels and signifiers fail because upstream references have no fields for
them. Unchanged built-in signifier snapshots are default behavior and can be omitted. A target whose local/external classification cannot be recovered from its
text also fails. Strict upstream export rejects populated reference metadata and
tooltips at their exact property, including explicitly empty values.

In the acdc profile, references retain `id`, inline-array `tooltip`, and
`metadata.attributes`, `metadata.roles` and `metadata.options`. A present empty
tooltip stays `[]`; absent metadata fields stay absent. Reference controls retain
the same string/presence rules as inline images. Nondefault xref styles, caption
labels, signifiers and independent target classification still fail explicitly.

Strong, emphasis and code spans retain IDs and ordered role tokens. An attributed
highlight exports as `variant: "generic"`; an ordinary highlight stays `mark`.
This distinction also preserves an explicitly empty role. Span metadata permits
only roles. Inline image and reference metadata permit roles, options and scalar
attributes, with no block location or positional fields. Node and content locations
remain separate from ID-token coordinates, which have no ASG field.

For example, `[.review]#Text#` exports as a generic span with
`metadata.roles: ["review"]`, while `#Text#` exports as a mark.
link:../../fixtures/asg/inline_metadata.adoc[The inline metadata fixture] and its
link:../../fixtures/asg/inline_metadata.json[checked JSON] cover links, mail,
xrefs and formatted spans with a nested image. Inline IDs retain untitled target
semantics; duplicate IDs and independent reference catalog values still fail.

== Resolved substitution effects

Both export profiles preserve the effects of supported block `subs=` settings.
Formatting, expanded attributes, macros, typography and character references
come from the resolved nodes. Ordinary body text exports as `text` when special
character escaping is active, or `raw` when it is disabled. This treatment follows
formatting spans and explicit link labels. A verbatim body retains its actual
block form and can contain formatted children without losing their literal text.

Titles, alternative text and tooltips keep their own content boundaries. Raw
fragments also keep their own treatment: a protected fragment with one remaining
special-character stage becomes `text`, even inside an unescaped body. A raw
passthrough remains `raw`. Automatic reference labels retain their existing
fallback behavior.

The original list/group/modifier spelling is source-only once these effects are
represented. Equivalence tests compare explicit settings with ordinary text or
protected/raw passthrough nodes. No additional policy field or compatibility
selector is needed in the graph, and export never repeats language substitutions.
Standalone inline export uses normal escaping and has no surrounding block
context. Export the document when body `subs=` or a verbatim context matters.
Unknown block instructions and unresolved raw operations still fail at a specific
property. Parser compatibility mode and Cargo features do not select export policy.
link:../../fixtures/asg/substitutions.adoc[The substitution fixture] and its
link:../../fixtures/asg/substitutions.json[checked JSON] show these boundaries.

== Ordered document attribute events

The document's `attributes` object remains the end-of-header snapshot. In the
acdc profile, accepted body assignments occupy their existing position in the
`blocks` array. The node's discriminator is separate from the attribute's name:

[source,json]
----
{"name":"attribute","type":"block","attribute":"imagesdir","assignment":{"kind":"set","value":"images"}}
{"name":"attribute","type":"block","attribute":"imagesdir","assignment":{"kind":"unset"}}
----

A set value is a string: presence is `""`, literal false is `"false"`, and integers
retain their attribute-reference spelling. An unset has no `value` field.
Events inside supported nested bodies stay in those bodies. Consumers visit
these arrays in order; the exporter does not replay assignments or repeat
substitutions. This retains settings such as a later `imagesdir` change that
still affects media conversion after inline attribute references are resolved.

Known event locations are retained. Protected values that cannot fit a scalar,
rejected assignments and unresolved parser-prefix events fail explicitly. Strict
upstream export still rejects body events. Unsupported table/cell owners also
continue to fail, so their scope cannot be silently lost.
link:../../fixtures/asg/body_attributes.adoc[The ordered-event fixture] and its
link:../../fixtures/asg/body_attributes.json[checked JSON] show header values,
set/unset events, metadata-adjacent assignments and nested media.

== Lists

Ordered and unordered lists preserve the list marker and each item's marker,
principal text and attached blocks. An item's level can be omitted only when its
marker gives the same level. Description-list terms stay inline arrays inside the
required `terms` array. Each native item supplies one term; export does not merge
adjacent definitions. A single ordinary item ID and reftext are supported; aliases
and bibliography identity are rejected. Delimiter-token coordinates are source
provenance without an upstream field; the item's full location is preserved.

Callout markers describe the resolved tree: explicit markers contain the stored
number; automatic markers use `<.>` and recover the number from item position.
The list marker comes from its first item. Invalid authored numbers have already
been diagnosed and normalized by the parser; export does not recreate their
source spelling. An automatic number that disagrees with item position is rejected.
Inline callout references and their associations remain unsupported.

Empty lists, checklist state, independent levels, unsupported nested content and
sections inside item attachments fail explicitly. Supported list metadata and
catalog entries use the same rules as other supported blocks.

== Blocks and media

Supported delimited bodies keep their opening delimiter. Literal, listing and verse
bodies can contain verbatim leaves because the owning block preserves their
presentation. Code in an ordinary paragraph still fails. Indented and styled leaf
paragraphs retain their source form from the native paragraph and its retained
pre-inline source; export does not invent a delimiter. Parent paragraph
forms and synthetic quote markers require the named acdc profile.

Audio, video, image and TOC nodes use macro form. Targets come from the native source;
video playlists remain one complete target, including commas. The provider selector stays in
its retained `poster` attribute, as supplied by the native owner. Retained positional slots follow the selected parser
policy; a consumed provider is not reinserted as an extra slot. Discrete headings
retain their level and present title, and page/thematic breaks retain their variant.
Single ordinary identities use the same rules as other supported owners.

Every semantic property must still have a mapping. Parsed captions, including
unnumbered caption state, and explicit image alternative content are rejected until
supported by a named content extension. Uncaptioned library-built listings, examples
and images can be exported. Tables and block STEM remain unsupported.

Delimited admonitions retain their actual opening delimiter in both profiles,
including open-block `--` and longer example delimiters. Source-free library
construction without a supplied form is rejected.

The named acdc profile adds three closed forms:

* Paragraph/indented admonitions keep `blocks` and their `variant`, with no delimiter.
* Styled parent paragraphs (sidebar, example, quote, abstract and partintro) keep
  their native `inlines` and paragraph/indented `form`. Export adds no child paragraph.
* Marked quotes use `form: "marked"`, `marker: ">"` or `marker: "\""`, and their
  native `blocks`. A single source marker is not a paired delimiter.

`fixtures/asg/block_forms.adoc` and its checked JSON demonstrate these forms.
Strict export rejects them where the pin has no corresponding form. Unsupported
nested meaning still reports its complete property path.

== Semantic regression checks

The parser tests run every source fixture in both compatibility modes. Expected
JSON records the selected language behavior; it is not an upstream-schema claim.
`tests/attribute_contract.rs` checks a compact set across public reads, native JSON
and checked ASG: introduced title formatting, caption prefixes, literal quote
content, declaration snapshots, image text, selected-only footnotes and empty
versus absent values. A deliberately wrong title still passes the schema and
fails the expected semantic comparison.

Run the export tests with `--all-features`, or with
`--no-default-features --features asg` to check the same contracts without parser
capabilities. CI uses the vendored schemas and a fixed TCK revision. The TCK
runner reports the supported subset; an explicit rejection or a failed case
remains a failure. Its result does not replace the native fixture or converter
regression suites.
