= `acdc-converters-pdf`

`AsciiDoc`-to-PDF converter backed by the Rust https://typst.app[Typst] engine.

The crate turns the acdc AST into Typst markup, resolves document assets, and returns PDF bytes through the shared converter interface.
The command-line backend is optional and is not part of the default `acdc` build.

== Usage

[source,console]
....
acdc convert --backend pdf document.adoc
....

The derived output path is `document.pdf`.
PDF-specific options can add page headers, footers, and branding:

[source,console]
....
acdc convert --backend pdf document.adoc \
  --font-dir fonts/brand \
  --logo assets/logo.svg \
  --title "Internal Architecture" \
  --watermark "Internal Copy" \
  --watermark-timestamp
....

Use `--page` and `--page-layout` to set the document paper and orientation.
The equivalent document attributes are `pdf-page-size` and `pdf-page-layout`;
explicit CLI or `PdfOptions` values take precedence.
Supported named sizes are A3, A4, A5, Executive, Legal, Letter, and Tabloid.
`pdf-page-size` also accepts custom dimensions as `[width, height]` or
`width x height`. Dimensions can use `in`, `cm`, `mm`, `pt`, `px`, or `pc`;
unitless values are PDF points.

Use `pdf-page-margin` to override the theme margins for one document. It accepts
one to four measurements in CSS order, such as `[1in, 0.75in, 1in, 0.75in]`.
Invalid dimensions or margins produce a structured warning and use the standard
page or theme fallback.

== Current scope

The backend currently renders:

* document titles, subtitles, title pages with author and revision details, PDF metadata, sections, discrete headings, and section numbering
* automatic, preamble, and macro-placed tables of contents, including custom titles and depth
* bold, italic, monospace, highlight, subscript, and superscript text
* links, cross-references, footnotes, inline anchors, and common UI macros
* visible and concealed index terms with generated, page-linked index catalogs
* ordered, unordered, description, checklist, and callout lists
* tables with widths, page placement, semantic repeating headers, column/row spans, frames, grids, and row stripes
* admonitions, examples, open blocks, sidebars, abstracts, quotes, verse, passthrough blocks, thematic breaks, and page breaks
* paragraph and document hard line breaks
* listing and literal blocks, plus source blocks with bundled syntax highlighting, line numbers, highlighted lines, and callouts
* collapsible examples as expanded disclosures with their full content visible
* local, remote, and `data:` URI images in block and inline positions
* static audio and video fallbacks with clickable source links and linked video posters
* a configurable page theme, header logo, watermark, footer, standard or custom page dimensions, per-document margins, and portrait or landscape layout

== Known limitations

The backend is intentionally incomplete.
Stem notation uses an escaped textual fallback.
AsciiMath and LaTeX translation are not yet implemented.

When `source-highlighter` is set, source blocks use the bundled Typst syntax theme.
PHP source blocks marked `%mixed` use Typst's normal PHP highlighter and emit one warning per document because Typst does not support that mixed mode.

Audio and video blocks render as static media fallbacks because PDF cannot play embedded media through the HTML controls.
Each source is a clickable link with a media label, and block titles render as captions below the fallback, matching Asciidoctor PDF.
Local media links use `imagesdir`; playback options such as start and end times, autoplay, looping, and controls do not affect the static result.
When a video has an available `poster`, the poster is linked to the first video source and any additional sources remain as separate links.
Poster loading follows the same safe-mode, network, size, and strict-asset rules as document images, but playable media is never fetched.
The converter emits one warning per document when it uses a static media fallback.

Inline icons use text when `icons` is unset, bundled Unicode glyphs when `icons=font`, and files from `iconsdir` for other set values.
The glyph mode covers common directional and status icons rather than the full Font Awesome catalog used by Asciidoctor PDF; an unknown name uses its text alternative.

PDF output cannot preserve interactive open and closed states.
Examples marked `%collapsible` always render expanded with a disclosure marker and their title, or `Details` when untitled.
The `%open` and `%closed` options therefore produce the same PDF output.

Normal page breaks do not add a blank page when they occur at an existing page boundary; add `%always` to force another page.
The document-level `pdf-page-layout` attribute selects portrait or landscape output.
The `page-layout` attribute and the `portrait` and `landscape` roles on individual page breaks do not switch orientation.
Those page breaks keep the configured document layout.

Asciidoctor PDF's default theme renders the first laid-out line of an abstract in bold italic.
acdc uses a consistent italic weight for the full abstract body because Typst cannot style a line after layout.
This limitation is tracked in https://linear.app/silly-muppets/issue/SC-290/match-asciidoctor-pdf-abstract-first-line-emphasis[SC-290].

Source callout references use parenthesized numbers such as `(1)`.
Asciidoctor PDF instead uses circled number glyphs such as `①`.

An explicit block `line-comment` value, including an empty one, leaves XML-style
callouts literal in acdc, matching Asciidoctor HTML, manpage, and unhighlighted PDF.
Asciidoctor PDF's highlighted source path ignores that setting and can turn the
same XML text into callouts. acdc keeps recognition independent of highlighting.
This follows acdc's chosen SDR-5 policy of separating parsing and conversion.
PDF output removes the prefix selected by a block's `line-comment` attribute;
an empty value preserves all prefixes. These settings apply with and without
highlighting, matching unhighlighted Asciidoctor PDF. Its highlighted source
path instead strips the default prefixes and ignores custom and empty values.
One optional ASCII space may follow a prefix; spaces within the prefix remain
part of the required match. Escaped markers and disabled callouts stay literal.

Attribute-expanded prefixes are eligible for removal in acdc's parsed code,
while Asciidoctor retains them because of its substitution order. Prefixes
inside passthroughs or formatted spans remain part of those spans.

acdc treats `[X]` as a checked list marker, alongside `[x]` and `[*]`.
Asciidoctor PDF leaves `[X]` in the item text.
This is an intentional parser extension shared by all acdc converters.

Table row stripes continue by logical row number when a table crosses a page.
Asciidoctor PDF restarts the stripe cycle after each repeated header.

Table roles have no general PDF theme hook.
The `left`, `center`, and `right` roles control placement, and `stretch` controls width.
Other table roles are ignored without warnings, matching Asciidoctor PDF.

Block images with `float=left` or `float=right` render on the requested side, but following text starts below the image.
Typst does not yet support wrapping paragraph text beside a floating image, so the converter emits a warning for each affected image.
Native side wrapping is tracked in https://github.com/typst/typst/issues/5181[Typst issue 5181].

Raw inline passthrough content is always emitted through Typst's escaped text boundary.
Unlike Asciidoctor PDF, backend-specific markup in `+++...+++` or `pass:[]` is displayed literally and cannot execute Typst code.

== PDF substitutions for browser-only behavior

PDF uses static, print-oriented output for features that need a browser or an interactive document.
The detailed limitations above apply to these substitutions.

[cols="2,3",options="header"]
|===
| Browser-only behavior
| PDF output

| Collapsible open and closed states
| An expanded disclosure with a marker and title.

| Audio and video playback controls
| Labelled links to each source, with an available video poster linked to the first source.

| CSS, webfonts, and dark mode
| The PDF theme, explicitly trusted font directories, and fixed print colours.

| Link windows, targets, tooltips, and relationship metadata
| A normal clickable PDF link; browser-only attributes do not change it.

| Text wrapping beside floated images
| The image is aligned to the requested side, following text starts below it, and the converter reports the fallback.

| HTML document frames, docinfo, CSP, and DOM or ARIA choices
| No direct equivalent. PDF always produces a complete document and adds PDF structure and image alternative text where supported.

| HTML terminal previews and asciicast replay
| No interactive PDF equivalent; use the HTML backend when the replay is required.
|===

== Index catalogs

Add an `[index]` section to generate a cumulative catalog of registered index terms.
Body terms register when their content is rendered, so later body terms do not appear in an earlier catalog.
Asciidoctor PDF also registers terms in headings when it prepares automatic heading IDs.
acdc follows this behavior: an early catalog can include later heading terms without page numbers.
Headings with an explicit ID, or with `sectids` unset, register only when rendered.
Visible `((term))` and `indexterm2:[term]` forms remain in the document.
Concealed `(((primary, secondary, tertiary)))` and `indexterm:[primary, secondary, tertiary]` forms appear only in the catalog.

Use `term >> other term` or `see=other term` to direct readers to a replacement entry.
The replacement is shown as `(see other term)` and the source entry has no page numbers.
Use `term &> related term` or `see-also=related term` to add one or more `(see also related term)` entries while keeping the source entry's page numbers.
For screen media, a relationship target links to an exact primary-term match; a missing target remains text.
Non-screen media renders relationship targets without links.

acdc keeps relationship text and page locators for footnote terms registered before the index.
These are intentional differences from Asciidoctor PDF 2.3.15, which ignores relationship metadata and can list footnote terms without locators.
Later body and footnote terms still remain outside an earlier catalog.

For screen media, each page number links to the exact term occurrence.
The default screen sequence lists every occurrence.
Set `:index-pagenum-sequence-style: page` to list each page once, or set it to `range` to combine consecutive pages.
For non-screen media, the catalog ignores that sequence setting and emits unlinked, unique page numbers with contiguous ranges, matching Asciidoctor PDF.
An empty index section is omitted, and content inside an index section is ignored, matching Asciidoctor PDF.

Use `subs=+macros` to enable index terms in listing and literal blocks.
PDF page references follow their code lines, including when long lines wrap across pages.
Newlines inside an index label become spaces; surrounding code whitespace stays unchanged.
Attribute and quote substitutions affect catalog labels only when they precede macros.
For example, with `subs="macros,attributes"`, `((term {name}))` displays the expanded name but registers `term {name}` in the catalog, matching Asciidoctor.

The bundled theme uses two columns with a 12 pt gap.
Use `[index%notitle]` to hide the visible section heading.
The `index.columns` and `index.column_gap_pt` theme tokens set the column count and gap.
Set `index.columns` to `1` for a single-column catalog.
In a custom theme, a `null` or omitted `index.column_gap_pt` uses the body font size.

== Document language

The document `:lang:` attribute sets the Typst text language.
Use a two- or three-letter language code, such as `pt` or `eng`.
An optional two-letter region can follow `-` or `_`; for example, both `pt-BR` and `pt_BR` become Typst `lang: "pt", region: "BR"`.

Missing or empty values use English.
Values that Typst cannot represent also use English and produce a converter warning.
Asciidoctor PDF accepts arbitrary `lang` values, but Typst requires separate, valid language and region codes.

== Accessibility

PDF output includes a semantic tag tree and document-language metadata. Typst
maps supported headings, paragraphs, lists, tables, figures, links, and images
to PDF structure roles. Image descriptions from AsciiDoc reach the tagged PDF
as alternative text.

This is baseline tagged PDF output, not a claim of PDF/UA-1 conformance. The
pinned Typst release can enforce PDF/UA-1, but that mode can reject documents
that do not meet its metadata and semantic requirements. acdc does not enable
that stricter profile automatically.

== Named destinations, inline IDs, and roles

Rendered reference IDs create public PDF named destinations using their original AsciiDoc names.
This includes document titles, sections, blocks, inline anchors, formatted spans, and IDs on explicit `link:`, direct URL, and `mailto:` macros.
For example, `[[chapter]]` on a section and `anchor:term[]` in its text can be reached through `manual.pdf#nameddest=chapter` and `manual.pdf#nameddest=term` in supporting viewers.
Targets inside inline code and code blocks with macros enabled are also exported.
Links and cross-references inside backticks remain clickable while retaining monospace text:

[source,asciidoc]
----
`https://example.org[Site]`
`xref:chapter[Chapter]`
----

Automatic link labels honour `hide-uri-scheme`; external cross-references honour `relfilesuffix` at their source position.
Links copied into TOC entries or automatic reference labels retain the enclosing navigation target; the original heading link remains clickable.
Footnotes in those copied titles display their existing number without adding
another footnote body or definition. Normal footnote references retain their
native PDF links.
Nested links keep separate click targets, and anchors inside link labels retain their full label text; Asciidoctor PDF can leave these cases as literal or incomplete markup.
Content omitted from PDF output creates no destination.
Local cross-references can appear before or after these targets.
When several anchors precede a document title, the last anchor is used and automatic references show the full title and subtitle.
For duplicate IDs, acdc keeps the first rendered destination so the PDF remains valid.
Authored IDs take precedence if they collide with automatically encoded heading names.
acdc also exports its broader Unicode IDs, such as `topic🚀`, which Asciidoctor leaves literal.

IDs on bold, italic, monospace, highlight, subscript, superscript, and quoted text create PDF link targets.
For example, `[#term]*Term*` can be referenced with `<<term>>`.
Without explicit link text, the reference renders as `[term]`.

The PDF backend supports these built-in roles:

* `big` and `small` change the text size.
* `underline`, `overline`, and `line-through` decorate text.
* `aqua`, `black`, `blue`, `fuchsia`, `gray`, `green`, `lime`, `maroon`, `navy`, `olive`, `purple`, `red`, `silver`, `teal`, `white`, and `yellow` set the foreground colour.
* Matching `*-background` roles set the background colour.

Use `[.underline]#text#` to apply a role or `[.red.underline]#text#` to combine roles.
The same roles apply to URL, link, and mailto text through the macro's `role` attribute.
Browser-only `window`, `target`, `title`, `rel`, and `opts` attributes do not affect PDF output.
Unknown roles are ignored without warnings and cannot yet be styled through PDF themes.
Highlighted text keeps its default background only when it has neither an ID nor a role.
An attribute list makes `#...#` a generic attributed span, matching Asciidoctor PDF.

== Options

The CLI flags map to fields on `PdfOptions` for library callers.

[cols="1,1,3",options="header"]
|===
| CLI | `PdfOptions` field | Effect

| `--font-dir`
| `font_dirs`
| Add an explicitly trusted directory of `ttf`, `otf`, `ttc`, or `otc` fonts.
  Repeatable.

| `--logo`
| `logo`
| Add an SVG or raster image to the page header.

| `--title`
| `title`
| Override the page-header title.
  The full document title, including its subtitle, is the default.

| `--watermark`
| `watermark`
| Add diagonal watermark text to every page.

| `--watermark-timestamp`
| `watermark_timestamp`
| Add a timestamp to the footer.
  Library callers supply the displayed string.

| `--page`
| `page`
| Set A3, A4, A5, Executive, Legal, Letter, or Tabloid.
  `PageSize::try_custom` also accepts validated dimensions for library callers.
  `:pdf-page-size:` is consulted next and accepts named or custom sizes; A4 is
  the fallback.

| `--page-layout`
| `page_layout`
| Set `portrait` or `landscape`.
  `:pdf-page-layout:` is consulted next; portrait is the fallback.

| `--theme`
| `theme`
| Load a theme YAML file instead of the bundled neutral theme.

| `--plain`
| `plain`
| Remove the page background, header, and normal footer. Explicit watermark
  annotations remain visible.

| `--toc`
| `toc`
| Request a table of contents even without a document `:toc:` attribute.

| `--strict`
| `strict_assets`
| Turn image and logo resolution failures into conversion errors.

| `--emit-typst`
| `emit_typst`
| Also write the generated Typst markup to a debugging path.
|===

Only directories supplied through `font_dirs` are searched.
The converter does not discover fonts from the working directory or source tree.

The bundled serif, sans and monospace families include bold italic faces.
Nested styles retain the enclosing style after the inner span, matching Asciidoctor PDF:

[source,asciidoc]
----
*Bold _both_ bold again* normal.
----

Here, `both` is bold italic. The following text returns to bold, then normal.
Formatting inside backtick spans and their link labels is retained as well.
Custom font families need suitable faces for the combinations they use.

IBM Plex Math is bundled as a symbol fallback, including the double arrows
`⇒`, `⇐` and `⇔`. Fonts must contain the glyphs used in the document.
Missing glyphs produce a converter warning that identifies the affected text and Unicode code points,
once per distinct text cluster after font fallback. PDF text extraction can
return the original characters even when their glyphs are missing; it does not
prove that they are visible.
acdc reports missing glyphs even where Asciidoctor PDF silently emits a
replacement glyph. Default symbol coverage also differs between the bundled
fonts; for example, acdc supplies `⇔` without configuring a fallback theme.

For CJK text, supply fonts that cover the required language with `--font-dir`.
For a specific family order, configure the theme's `body_font`, `heading_font`
and `mono_font` fallback lists. Asciidoctor PDF's default fonts also lack many
CJK glyphs; its `default-with-font-fallbacks` theme provides broader coverage,
but does not cover every language.

Literal backticks and spacing acute accents retain their positions instead of
attaching to the preceding letter. Combining accents remain enabled.

With the default `pre-spec-subs` feature, block-level `subs=` controls PDF text substitutions in the same way as the other compatible converters.
In particular, `subs=-replacements` suppresses typography replacements and `subs=+replacements` enables them in literal/listing content.

Titles use normal substitutions independently of the block body, matching
Asciidoctor PDF. For example, `.Title (C)` renders as `Title ©` even when the
body uses `subs="none"`, including on verse, literal and listing blocks and
inside AsciiDoc table cells. An inline passthrough such as `pass:[(C)]` keeps
that part of the title literal.

Verse paragraphs and delimited verse blocks use normal inline substitutions
while preserving authored line breaks and indentation. Formatting, links,
footnotes, anchors and index terms remain active; body `subs=` settings and
inline passthroughs can disable the corresponding substitutions.

== Asset access and safe mode

Local document images are resolved relative to the source document.
Image access then follows the converter safe mode:

* `unsafe` permits local and remote sources.
* `safe` confines local paths to the source directory and permits remote sources when the `network` feature is enabled.
* `server` also confines local paths and requires `:allow-uri-read:` for remote sources.
* `secure` rejects document image sources.

The header logo is an explicit application or CLI option, so safe mode does not block it.
Failed images render fallback text unless strict mode is enabled; a failed logo is omitted.

Fetching remote `http` or `https` images requires the off-by-default `network` Cargo feature.
The CLI's `network` feature forwards it.
Without that feature, remote images produce per-image warnings, or errors under `--strict`, while the rest of the document continues to render.
Local and `data:` URI images are unaffected.

== Trust boundaries and limits

Custom theme content is configuration data, not Typst source.
The theme schema is strict, token values are validated, and emitted font names are escaped.
Theme files are limited to 1 MiB, including when a file grows while it is being read.

Resolved images are validated and copied to private snapshots before Typst can read them.
The image resolver bounds each input and prevents SVGs from loading external file references.

Unsupported stem content is emitted through the escaped text boundary and cannot add Typst statements.
Explicit font directories are application input, not document input.

PDF compilation still runs in-process, so safe mode is not a CPU or memory sandbox.
Applications accepting untrusted documents should apply document, asset, font, CPU, memory, and concurrency quotas around conversion.

== Architecture

The converter keeps orchestration and AST emission local.
Existing helper crates own the boundaries that need different dependencies:

[source]
....
converters/pdf
  └─ crates
     ├─ theme   acdc-pdf-theme: validated design tokens and bundled assets
     ├─ typst   acdc-pdf-typst: escaped Typst writer and themed preamble
     ├─ images  acdc-pdf-images: bounded image resolution and snapshots
     └─ render  acdc-pdf-render: font loading, Typst compilation, and PDF export
....

Only `acdc-pdf-render` depends directly on the Typst compiler.
No additional converter layers are intended; follow-up work should remain in these existing boundaries.
