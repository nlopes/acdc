= `acdc-pdf-images`

Resolves local paths, `file://` and remote `http(s)` URLs, and `data:` URIs for
acdc's PDF output. The map contains paths to validated image snapshots. The
renderer reads each file when needed for layout.

This is an internal workspace crate. It is not published to crates.io and has no stability guarantees outside the `acdc-pdf-*` pipeline.

== Where it sits

[source]
....
converters/pdf  ──▶  acdc-pdf-images  ──▶  acdc-pdf-render
  (walks the AST,      (fetch + detect +      (reads each image's file
   collects URLs)       hash + spool)          at its virtual path, on demand)
....

The converter walks the document tree and hands this crate a list of image reference strings. This crate is deliberately *IR-agnostic*: it knows nothing about the AsciiDoc AST, only strings in and a map out. The emitter references each image by the `virtual_path` this crate assigns; the renderer reads the file at that same path, so the reference and the file can never drift apart.

=== Memory

The map stores a *path* for each image. Every validated source is copied into
the caller-owned spool directory, including local files. Changing a source
after resolution cannot change the snapshot used by the renderer. This crate
holds one image at a time with sequential fetching. Parallel remote fetching
holds one capped encoded response per worker in a batch. Validation and
snapshot writes remain sequential. Typst loads the snapshots for layout.

== What it does

`resolve(urls, config)` processes each reference and returns a `Resolved { assets, failures }`. Repeated references to the same source string are resolved once:

. **Fetch** source bytes from `data:`, remote `http(s)`, `file://`, or a bare
  local path. Scheme matching is case-insensitive. Relative paths resolve
  against the configured `base_dir`. `SourcePolicy` can deny all sources or
  confine local paths to `base_dir`. Confined paths are checked after resolving
  symlinks. Reads enforce the encoded size cap, including after HTTP content
  decompression.
. **Detect and validate** the format from the bytes themselves (magic bytes, not the URL extension). Raster images are fully decoded with a 256 MiB allocation cap. SVGs are parsed with `usvg` without loading external file references; inline data images remain supported.
. **Content-hash** the validated bytes into a stable `/images/<hash>.<ext>` virtual path and atomically persist a snapshot under `spool_dir` (identical bytes are written once). The `ResolvedImage` carries the resulting path, not the bytes.

A reference that fails any step is recorded in `failures`. Ordinary image failures
do not stop resolution. Quota failures stop new fetches and leave earlier images
available. The caller decides policy: `converters/pdf` turns failures into
structured warnings, or hard errors under `strict_assets`.

=== Document limits

Each `resolve` call attempts at most 1,024 distinct source strings and accepts
up to 100 MiB of encoded image data by default. The per-image limit remains
20 MiB. These limits are specific to acdc.

Sources are processed in input order. A failed attempt uses one source slot.
Repeated identical strings use one slot and are reported once. Different
strings each use a slot and charge their full accepted image size, even when
their content matches. Matching content still shares one snapshot on disk.
This accounting also applies when the snapshot already exists.

The byte limit applies after base64, percent, or HTTP content decoding, before
image decoding. Each read is capped at the smaller of the per-image limit and
the remaining total allowance. Failed images do not use accepted bytes. Once
the total allowance is used, or an image would exceed it, later sources fail
without being fetched. Earlier images remain available. A zero source or byte
limit prevents all fetches.

For example, a source limit of two permits two distinct image attempts. A
missing first image still uses a slot. A byte limit of 10 MiB permits two
5 MiB sources, including two URLs with identical content. A third source is
not fetched.

Limits restart on each call. Trusted callers can raise them with
`with_max_sources` and `with_max_total_bytes` before calling `resolve`.

== The `network` feature

Remote `http(s)` fetching lives behind the `network` feature, which is **off by default** to match the workspace-wide convention (a `--no-default-features` build links no HTTP stack). It is forwarded up through `converters/pdf` to the CLI's own `network` feature.

With the feature off, a remote reference resolves to a `NetworkDisabled` per-image failure; local files and `data:` URIs are unaffected.

=== Parallel remote fetching

Remote fetching permits two simultaneous HTTP(S) requests per `resolve` call
by default. Use `with_remote_concurrency(1)` for sequential fetching, or
`with_remote_concurrency(4)` to permit four requests. Zero also selects
sequential fetching. This setting does not enable network access or change
source policy. Local files and `data:` URIs remain sequential.

Consecutive remote sources form batches. Each request reserves the full
per-image byte allowance before it starts. Source slots and the remaining
document byte allowance can reduce the batch size. For example, with a 20 MiB
per-image cap and 35 MiB remaining, the next request stays sequential. When
the document allowance is below the per-image cap, exceeding it stops later
fetches. Validation, snapshots, and failures keep input order. A failed image
does not cancel other permitted requests.

Parallel fetching retains more encoded image data while the batch completes.
The setting bounds request count; it does not bound total conversion memory.

=== Worker failures

Each remote request has a 30-second HTTP deadline by default. Use
`with_timeout` to change it. The deadline covers DNS lookup, connection
establishment, response headers, and the response body. Receiving more bytes
does not restart it. Image validation and the complete document have no
deadline from this setting.

A batch waits for all its requests to finish or time out. A failed request
records an image failure. Other permitted images remain available. Failed
downloads do not create snapshots. Validation and snapshot writes start after
the batch completes.

The resolver waits for its image workers to exit. It cannot forcibly stop a
deadlocked thread. In builds with `panic = "unwind"`, a worker panic becomes
an image failure. The workspace release profile uses `panic = "abort"`, so
a panic terminates the process. Cleanup is not guaranteed after process
termination.

== `ResolveConfig`

[cols="1,3"]
|===
| `base_dir` | Directory relative image paths resolve against.
| `spool_dir` | Private caller-owned directory where every validated image snapshot is written. The caller cleans it up after rendering.
| `with_timeout` | Per-request HTTP deadline, from DNS lookup through the response body. Default 30 seconds. Has no effect without `network`.
| `with_max_bytes` | Size cap enforced per image across *every* source; anything larger is a per-image failure. Default 20 MiB.
| `with_max_sources` | Maximum distinct source strings attempted per call, including failures. Default 1,024.
| `with_max_total_bytes` | Maximum accepted encoded image bytes per call. Different source strings each count, including matching content. Default 100 MiB.
| `with_source_policy` | `Unrestricted` (default), `Confined { allow_network }`, or `DenyAll`. Confined local paths must remain beneath `base_dir` after canonicalization.
| `with_remote_concurrency` | Maximum simultaneous remote image requests. Default two. Zero or one selects sequential fetching. Quotas can reduce the batch size.
|===

Construct the configuration with `ResolveConfig::new(base_dir, spool_dir)` so
both paths are explicit. Chain the `with_...` methods to set optional values.
The fields are private. The caller owns the spool directory and removes it
after rendering finishes.

[source,rust]
----
use std::time::Duration;
use acdc_pdf_images::{ResolveConfig, SourcePolicy};

let unrestricted = ResolveConfig::new("project", "private-spool")
    .with_remote_concurrency(4);

let confined = ResolveConfig::new("project", "private-spool")
    .with_source_policy(SourcePolicy::Confined { allow_network: false })
    .with_timeout(Duration::from_secs(10))
    .with_max_bytes(5 * 1024 * 1024)
    .with_max_sources(100)
    .with_max_total_bytes(25 * 1024 * 1024);

let disabled = ResolveConfig::new("project", "private-spool")
    .with_source_policy(SourcePolicy::DenyAll);
----

To migrate field assignments, replace `config.max_sources = 100` with
`config = config.with_max_sources(100)`, or set the value in the constructor
chain. Keep the directory paths in the caller if they are needed later.

== Testing

Per the workspace convention, run with `--all-features` so the mockito-backed remote-fetch tests are exercised:

[source,console]
....
cargo nextest run -p acdc-pdf-images --all-features
....

Without the `network` feature the remote tests are compiled out and a test covering the disabled path runs instead.

Run the manual latency check with controlled local responses. It compares
one and four workers without asserting a timing ratio:

[source,console]
....
cargo nextest run -p acdc-pdf-images --all-features \
  --run-ignored ignored-only -E 'test(remote_fetch_measurements)' \
  --success-output immediate
....
